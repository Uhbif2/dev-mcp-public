# dev-mcp

MCP-сервер для удалённой работы с кодом на Windows. Агент читает и меняет файлы,
ищет текст и запускает проверки только в каталогах, перечисленных в `policy.toml`.
Поверх ядра работает **fleet**: реестр проектов, очередь задач, захваты файлов,
слепое ревью, серверная приёмка и интеграция в Git.

Статус: экспериментальная система. Основной код и документация — на русском,
[главная страница](README.md) и [архитектура](ARCHITECTURE.md) — на английском.

## Установка

Нужны Python 3.11+ и Git; для проверок расширения — Node.js.

```powershell
uv sync --frozen --extra dev
copy policy.example.toml policy.toml
# Укажите свои каталоги в policy.toml.
.venv\Scripts\python.exe -m dev_mcp --check
.venv\Scripts\python.exe -m dev_mcp
```

Альтернатива без uv: `py -3 -m venv .venv`, затем
`.venv\Scripts\python.exe -m pip install -e ".[dev]"`.

По умолчанию это stdio-сервер: его запускает ваш MCP-клиент.
Для удалённого подключения нужен отдельно настроенный MCP-прокси или шлюз с
авторизацией. Лончер шлюза, модельные ретрансляторы и сторонние интеграции
в этот репозиторий не входят. `restart.cmd` предназначен для оператора,
который настроил собственный proxy launcher через `machine.toml`.

## Доступ

- `roots` разрешает чтение, `write_roots` — запись, `exec_roots` — запуск.
- При `allow_write = false` запись разрешена только внутри `write_roots`.
- `deny_patterns` проверяет каждый сегмент пути. Сервер запрещает обходы через
  `..`, junction, UNC, короткие имена Windows, ADS и похожие префиксы каталогов.
- `run` принимает массив argv, проверяет программу и аргументы и очищает
  окружение. Долгий запуск получает `job_id`; состояние доступно через `run_status`.
- `fetch_url` включается отдельно и проверяет SSRF на каждом перенаправлении.
- Изменённая политика перечитывается автоматически. Повреждённая не применяется.

Каталог с правом записи и запуска позволяет агенту исполнить собственный код.
Дочерний процесс не изолирован от остальной файловой системы или сети.
Выбирайте `exec_roots` с учётом этой границы доверия.

## Fleet и расширение

Начните с [протокола](docs/FLEET-PROTOCOL.md) и
`fleet-projects.example.toml`. Локальные пути и необязательные интеграции
задаются через `machine.example.toml` → `machine.toml`.
GitHub-публикация проектов и защита живого слушателя выключены, пока их явно
не настроил оператор.

[Fleet Tabs](extension/fleet-tabs/README.md) поставляется исходниками и
распакованным ZIP в [релизах](../../releases). В Chrome выберите «Загрузить
распакованное», затем задайте собственные URL проекта ChatGPT и имя коннектора
через `local-settings.json`. Новая установка выключена; список проектов
приходит от вашего сервера. Публичное расширение имеет отдельный ID.

Расширение управляет помеченными вкладками агентов. Черновики, вход, проверка
человека и ограничения сервиса останавливают отправку. Это экспериментальный
адаптер веб-интерфейса; соблюдайте условия сервиса для своего аккаунта.
Публикация в Chrome Web Store не выполнялась.

## Проверки и состав

```powershell
.venv\Scripts\python.exe -m pytest tests -q
cd extension\fleet-tabs
npm run test:all
```

Тесты, которым нужна живая конфигурация сопровождающего, явно пропускаются через
корневой `conftest.py`. Остальные работают с временными каталогами и фикстурами.
DOM-тесты используют отдельный headless Chrome с локальным макетом страницы.

В публичной версии нет личных проектов, очереди задач, истории чатов, ключей,
производственной политики и адресов инфраструктуры. Локальные настройки,
журналы и данные исключены через `.gitignore`. `.public-export.json` содержит
SHA-256 опубликованных файлов. MIT-лицензия — в [LICENSE](LICENSE).
