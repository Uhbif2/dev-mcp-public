# Агент владельца во вкладке ChatGPT

Агент в вкладке владельца следит за флотом и ставит работу без Claude Code. Задач из очереди не
берёт — надзирает. Механика флота — [FLEET-PROTOCOL.md](FLEET-PROTOCOL.md); локальный пульт — `fleet.cmd`.

Роль открывает пульт `fleet_owner`. Записи и запуска в dev-mcp и правки `policy.toml` она **не
даёт**: агент, сломавший dev-mcp, не починит его через сломанный dev-mcp. Постоянного `freeze` и
ручного approve нет — блокеры оттаивают сами.

## Начало — роль по номеру, без заявки (владелец, 15.11.2026)

ChatGPT блокирует вызовы с паролем или просьбой поднять права ещё до сервера — и после этого весь
чат. Роль выдаёт владелец у себя на машине — **любому агенту по его номеру**: метка вкладки и
заявка агента не нужны (раньше список «вкладок pult» забивался старыми и требовал просьбы агента).

1. Владелец видит номер агента (`worker_id`, например W10112) в его чате или в `fleet.cmd`.
2. `fleet.cmd owner-grant 10112 [10113 …] [--hours N]` (по умолчанию 12 ч; `W` можно не писать)
   или двойной щелчок по `owner-grant.cmd` → ввести номер. `owner-grant` без номера / `--list` —
   у кого роль; `--revoke [номер]` — снять. Выдача переживает перезапуск dev-mcp.
3. Агент — `fleet_owner(agent, 'status')`.

Чат, где уже заблокировали, не оживает — новый чат.

## Что ещё даёт роль

- **`fleet_browser(agent, tool, args)`** — агентский браузер владельца jev-browser (Chrome с его
  входами). `tool='list'` — каталог, `tool='schema', args={'name': …}` — аргументы; снимок — `browser_screenshot` (картинкой). Своя вкладка
  на агента, гаснет через 20 мин простоя; пароли — `browser_secret_fill` (значения не видны),
  нет записи — `browser_secret_request`/`browser_handoff`; оплата, удаление, письма, условия —
  только если задача прямо требует. В конце — `browser_close`. Без роли — отказ.
- **`fleet_quick(agent, command, args)`** — свои быстрые агенты (ниже). Ведущему доступно и без роли.

## Быстрые агенты — субагенты без очереди и ревью

Чат-субагент Claude Code, ведущего или агента с ролью: задача текстом уходит в новый чат ChatGPT
(его открывает расширение, метка `pult-q<N>`), ответ — **сразу владельцу**, без ТЗ, захвата,
приёмки, ревью и интеграции. Агент работает с `agent="Q<N>"` и правами владельца: у ведущего —
его захваты (страж записи считает их своими), у агента с ролью — роль (пульт, браузер); запись —
только в корне проекта задачи (или `--scope`). `fleet_take` быстрому агенту не выдаёт ничего.

| Кто | Команды |
|---|---|
| Claude Code | по умолчанию — суб-агент `fleet-quick` (`~/.claude/agents/fleet-quick.md`, правило в `~/.claude/CLAUDE.md`); вручную `fleet.cmd quick run [--scope P] [--project X] @файл` — поставить и дождаться ответа одной командой (в фоне); `fleet.cmd quick new --project X "текст"` (или `@файл`) → `q<N>`; `quick wait q<N>` (до ответа, ≤55 мин — в фоне); `quick show q<N>` (ответ, его действия в dev-mcp, тишина); `quick say q<N> "текст"`; `quick list`; `quick close q<N>` |
| ведущий / агент с ролью | `fleet_quick(agent, 'new', ['Проект', 'текст'])` (ведущему проект можно опустить); ответ приходит сообщением в конверт следующего вызова; `say`, `show`, `list`, `close` |

**Новый чат или прежний — выбор того, кто ставит задачу** (владелец, 15.11; умолчания нет): та же
тема и агенту пригодится уже прочитанное — `say` в его открытый чат; другая тема, другой объём или
чат разросся (ответы медленнее, путает контекст) — `new`. Открытый чат держит вкладку Chrome флота —
ненужные закрывай (`close`), закрытые расширение закрывает само.

**Права оператора (владелец, 15.11):** у быстрого агента Claude Code явный `--scope` (абсолютный
путь) — область оператора: `write_file`/`edit_file`/`run` там разрешены даже в `tree_deny` и вне
`write_roots`/`exec_roots` (так агент правит сам dev-mcp). Право ставит сервер на время каждого
вызова с `agent="Q<N>"` (`server._install_operator_delegation` → `policy.DELEGATED_ROOTS`), пока
задание открыто: `quick close` снимает его сразу. Маски секретов и страж флота действуют как обычно.
Коммит, push и restart агент не делает — их делает Claude Code после своей проверки. У быстрых
агентов ведущих и агентов с ролью права оператора нет.

**Цепочки:** `fleet.cmd quick new --after q1,q2 [--scope P] @файл` создаёт `waiting` без вкладки и слота; после ответа или закрытия каждого предшественника `quick.orders()` добавляет к первому сообщению их последние ответы (до 6000 символов на ID) и открывает задачу. Ответ последнего получай `fleet.cmd quick wait q3`. `quick wait --after N` по-прежнему означает номер ответа, а не зависимости.

**Перехват:** `fleet.cmd quick adopt qN-сессия [--force]` переносит быстрое задание между сессиями Claude Code после 30 мин тишины прежнего владельца (или с `--force`), сохраняя журнал.
**Итог:** исполнитель сдаёт полный отчёт через `fleet_quick(agent=tag, command='report', args=[...])`, затем продолжает `fleet_quick(..., command='park')`; `say` приходит в парковку без новой вкладки.

Книга — `data/fleet/quick/jobs.json`; модуль — `fleet/quick.py`.

## Команды `fleet_owner(agent, команда, args)`

| команда | args | что делает |
|---|---|---|
| `status` | — | платформа, исключения, захваты, живые воркеры, очередь |
| `report` / `active` | `[ПРОЕКТ]` | заявлено против сделано / кто держит какие пути |
| `metrics` | `--since ГГГГ-ММ-ДД` | метрики потока |
| `bootstrap` | `ПРОЕКТ TZ-NN […] [--reactivate]` | поставить в очередь ТЗ из `ToDo/tz` проекта |
| `reactivate` / `recover` | `ПРОЕКТ TZ ПРИЧИНА` | вернуть frozen → ready / молчащий taken → ready с сохранением файлов |
| `priority` | `ПРОЕКТ N` | приоритет проекта (меньше — раньше) |
| `say` | `ТЕКСТ` | сообщение всем держателям задач — только о свершившемся факте |
| `lock` | — | закрыть свою сессию |

## Поставить работу

ТЗ — файлом `ToDo/tz/TZ-NN-коротко.md` с yaml-шапкой; как писать, чтобы прошло ревью с первого раза, —
[CLAUDE-CODE-FLEET.md](CLAUDE-CODE-FLEET.md#поставить-работу). Главное: единица ТЗ — законченный
вертикальный срез (реализация + тесты + встраивание), а не файл или хелпер; `owns` не пересекается с
задачами в работе (`active`). Затем `fleet_owner(agent, 'bootstrap', ['<Проект>', 'TZ-NN'])` — пустой
`errors` значит «в очереди», чат под неё откроет расширение.
ТЗ с кодом включает **«Путь продукта»** (точка входа теста и контрпример);
`needs: [TZ-N#submitted]` открывает потребителя после сдачи до accept, а reject снова блокирует невзятого.
Полные причины предыдущих отказов ревью выдаются в брифе исполнителя.

## Что считать штатным

«Вернулась в очередь», «без ack», молчащий захват — штатно: молчащий захват maintenance вернёт сам
примерно через 30 мин; `recover` — аварийная кнопка. Авария — только платформа или транспорт, не
одна задача: сначала чинится инфраструктура, очередь продолжит сама.

Принятие ревьюером ещё не означает передачу результата. Проверяй цепочку
«принято → интегрировано → артефакт доступен» в метриках; архив появляется в
кабинете владельца и `fleet.cmd result <Проект>/TZ-NN`. Он содержит принятые
файлы, patch и квитанцию проверенной Git-версии. Развёртывание продукта и
приёмка владельцем требуют собственных подтверждений — доступность архива
их не заменяет. Если артефакта нет, смотри сохранённое ожидание интеграции
или гейта; повторная сдача задачи сама по себе это ожидание не снимает.
Тревога **«ПРИНЯТО, НО НЕ ЗАКОММИЧЕНО»** означает отсутствие окончательной квитанции интеграции.
Визуальное ревью выдаётся лишь агенту с `read_image/read_images`, иначе нужен новый чат с инструментами.
